# BOSS直聘与猎聘的平台行为模型（2026-09-12）

这份说明记录 JobPilot 当前采用的平台差异。它来自平台公开页面，目的是约束数据和自动化回执；它不是已经登录真实账号完成的端到端验收记录。

## 公开页面确认到的差异

| 项目 | BOSS直聘 | 猎聘 | JobPilot 的处理 |
|---|---|---|---|
| 主流程 | 平台强调求职者与 Boss 直接在线开聊 | 同时存在投递简历、与 HR/猎头在线沟通等入口 | BOSS 使用 `direct_chat`；猎聘使用 `application_and_chat` |
| 招聘者 | Boss、HR 等企业侧人员 | 企业 HR 与猎头均是明确角色 | 岗位记录保留 `recruiter_type/name/activity`，猎头身份不与企业 HR 混合 |
| 成功回执 | 进入会话、发出消息、交换/发送简历是不同事件 | 投递成功与在线沟通是不同事件 | 状态机分别记录 `contacted`、`message_sent`、`attachment_sent`、`submitted` |
| 地点 | 公开职位常见城市、区县和商圈 | 公开职位常见“城市-区县/商圈” | 拆为 `city`、`district`、`business_district`，先按城市分搜索任务 |
| 薪资 | 可见 K/月、元/月、元/天、元/时及“13薪”等格式 | 可见 k/月和“13薪—16薪”，也存在年薪 | 解析时保留周期与薪资月数；日薪、时薪、年薪不冒充月薪 |
| 学历/经验 | 常见“经验不限、1-3年、本科、学历不限” | 同时常见“3年以上、5-10年、统招本科” | 从经验标签提取保守最低年限；“统招”要求单独核对学历性质 |
| 公司信息 | 公开列表常见行业、融资阶段、规模 | 公开列表常见行业、融资/上市状态、规模 | 统一为 `industry`、`funding_stage`、`company_size`、`company_nature` |
| 求职安全 | 官方防骗指南列出培训、收费、刷单和站外联系等风险 | 同样应人工核对异常职位和沟通 | 文本只产生 `risk_flags` 复核提示；命中词本身不直接判定诈骗 |

依据：

- [BOSS直聘首页](https://www.zhipin.com/)及[使用帮助](https://www.zhipin.com/activity/cc/usehelp.html)说明直接沟通、个人中心投递/面试状态、简历隐藏和公司屏蔽等功能。
- [BOSS直聘公开职位页](https://www.zhipin.com/zhaopin/)展示薪资、地点、经验、学历、行业、融资阶段和公司规模等字段。
- [BOSS直聘防骗指南](https://www.zhipin.com/web/common/protocol/cheat-guide.html)列出传销、培训招生、收费、刷单和引导站外联系等风险特征。
- [猎聘首页](https://www.liepin.com/)的公开职位展示薪资月数、城市/区域、经验、统招学历、行业、融资/上市状态和公司规模。
- [猎聘智能招聘场景](https://ir.liepin.com/scenario/)说明在线直聊、云电话、HR/猎头直接沟通、反馈状态，以及结合简历与求职意向进行匹配和多轮调整。

## 筛选策略

平台筛选项常以标签或粗区间出现，用户条件却可能是“上海浦东、月薪下限 25K、年薪至少 35 万、13薪、双休、近 7 天发布、HR 近期活跃”。JobPilot 将它拆成两层：

1. **网页候选集**：在已验证的适配器中填写关键词，选择城市、地区、经验、学历、行业、规模等可用控件。
2. **本地精确复核**：对采集后的原始岗位字段重新执行完整 policy。网页薪酬区间只作候选集缩小；如果单选区间会漏掉仍符合条件的更高薪岗位，就不自动选择该区间。

`search-plan` 会为每个平台和城市生成独立任务，并在每项条件上标出 `site_exact`、`site_band`、`site_or_local` 或 `local_only`。这些标记是能力计划，不等于真实 CSS 定位器已经验证。

## 岗位去重与市场反馈

同一公司、岗位名、城市和规范化 JD 原文在 BOSS 与猎聘重复出现时，JobPilot 保留两条来源链接和各自沟通状态，但在“市场高频要求”中将它们归为一个保守岗位簇，避免重复发布把某个关键词虚假放大。只要 JD 文本不同就保留为两个岗位簇，避免把同公司同名的不同岗位误合并。

报告将要求分成三类：已有证据且写清、已有证据但表述不明显、现有底稿无证据。只有达到 `market_min_jobs` 的要求才进入高频区；单个 JD 仍有逐岗位诊断，但会明确提示不要据此堆关键词。

## 尚需真实账号验收的部分

仓库中的 `adapters/boss.json` 和 `adapters/liepin.json` 仍是不可执行的占位配置。公开页面访问会遇到登录或安全校验，因此以下内容只能在用户本机登录会话中逐项验收：当前筛选标签和定位器、列表是否真正刷新、聊天目标、点击沟通是否自动发送默认招呼、简历交换/附件入口，以及新消息或投递成功回执。

只读验收完成后，才应填写定位器并将相应私有适配器设为 `verified: true`。BOSS 与猎聘必须分别维护适配器，不能共用一套“投递成功”判断。
